# Образовательная платформа — кейс ФСП Чувашии

Веб-платформа дистанционной подготовки школьников 1–9 классов по спортивному программированию, по устройству близкая к Stepik. Ученик проходит курс сам, куратор сопровождает и проверяет работы, администратор собирает курсы.

| Папка | Что внутри |
|---|---|
| [`backend/`](backend/) | сервер на Go + SQLite: API, проверка ответов и кода, прогресс, рейтинг, сигналы отставания |
| [`ХакатонLastVersion/`](ХакатонLastVersion/) | интерфейс, последняя версия (HTML/CSS/JS по брендбуку). `js/api.js` подключает его к серверу |
| `Hackaton/` | предыдущая версия интерфейса (тоже подключена к серверу) |
| [`API.md`](API.md) | описание всех запросов API с примерами |
| `Demo_v6.1/` | статическая демо-версия интерфейса на localStorage (без сервера) |

## Запуск

Нужны **Go 1.22+** и **Python 3** (им проверяются решения задач).

```bash
cd backend
go run .
```

Откройте **http://localhost:8080**. Сервер сам создаст базу `backend/data/kotiki.db` и загрузит в неё три курса из базового пакета организатора и синтетических пользователей.

Порт меняется переменной `PORT`, остальные настройки — в [backend/README.md](backend/README.md).

## Что сделано

**Ядро кейса работает на сервере:** ученик входит, видит курс, проходит шаг, сдаёт задание, получает результат автоматической или ручной проверки, видит изменившийся прогресс; куратор принимает и возвращает работу; администратор собирает и публикует курс.

**Ученик**
- вход и самостоятельная регистрация;
- «Главная» со следующим шагом, карта курса со статусом каждого шага;
- шаги шести типов: теория, контрольный вопрос (один/несколько вариантов, число), Scratch, Minecraft Education, задача с тестами, проект;
- задачи на Python прогоняются по тестам (открытые + скрытые), вердикты OK / WA / TL / RE / CE по каждому тесту;
- ручные работы: ссылка, файл (скриншот), текст; статус и комментарий куратора;
- история всех попыток, вопросы куратору по конкретному шагу;
- объяснимый рейтинг: баллы по каждому шагу и типу шага, формула, место в группе.

**Куратор**
- очередь ручной проверки: работа ученика, критерии, условие шага, предыдущие попытки;
- принять (с баллами) или вернуть с обязательным комментарием;
- закреплённые ученики с сигналом отставания и **причинами** — сигнал появляется раньше, чем ученик перестаёт заходить: 3+ неудачные попытки подряд, отставание от группы, не исправленная работа, неактивность;
- ответы на вопросы учеников.

**Администратор**
- курсы: создание, паспорт, публикация и снятие, изменение опубликованного курса, удаление;
- модули и шаги: добавление, изменение, порядок, удаление (шаг с работами учеников уходит в архив, история сохраняется);
- редактор шага строится по описанию типа: поля содержания + настройки проверки (верный ответ, тесты, критерии, что сдаёт ученик);
- **новый тип шага без программиста**: экран «Типы шагов» → «Новый тип»;
- назначения «ученик → курс → куратор», пользователи.

## Как устроен курс (главное требование кейса)

Курс → модули → шаги. У шага два **независимых** свойства: **тип** (как выглядит) и **способ проверки** (`none` — прочитал, `answer` — сверка ответа, `tests` — прогон кода, `manual` — куратор). Все шаги лежат в одной таблице, различия — в JSON: `content` видит ученик, `check` — только куратор и система.

Поэтому модель выдержит курс, придуманный после хакатона:
- новый тип шага добавляет администратор в интерфейсе — база, сервер и интерфейс не меняются: содержимое рисуется по списку полей типа, форма сдачи — по `submit.fields`;
- один тип может проверяться по-разному: шаг Scratch в базовом пакете бывает и с ответом числом (автоматически), и со ссылкой на проект (куратор);
- новый способ проверки (например, другой язык) — одна реализация интерфейса `Checker` в `backend/internal/steps/checkers.go`.

Весь базовый пакет (3 курса, 9 модулей, 30 шагов) перенесён в эту модель: [backend/internal/seed/content.json](backend/internal/seed/content.json).

## Что не успели / ограничения

- Решения на Python запускаются отдельным процессом с лимитом времени, но **не в песочнице** и без лимита памяти. Для эксплуатации — контейнер с `--network none` или Judge0.
- Нет восстановления пароля и подтверждения почты.
- Загруженные файлы доступны по прямой ссылке со случайным именем.
- Все данные синтетические.
