# Образовательная платформа для школьников: решение кейса ФСП Чувашии

Сайт работает по адресу https://kodiki.su.

Платформа похожа на Stepik, но сделана для учеников 1–9 классов, которые готовятся к соревнованиям по спортивному программированию. Ученик проходит курс сам. Куратор отвечает на вопросы и проверяет то, что машина проверить не может. Администратор собирает курсы из шагов и назначает людей.

## Что реализовано

Всё работает на сервере, данные лежат в базе SQLite. Интерфейс берёт их через API, поэтому ученик, куратор и администратор видят одно и то же состояние.

**Содержание из ТЗ.** В базу перенесён весь пакет учебного содержания от организатора: 3 курса, 9 модулей, 30 шагов. Это Scratch для 2–4 классов, Minecraft Education для 3–6 классов и Python для 5–9 классов. Тексты теории, вопросы, правильные ответы, подсказки, тесты к задачам, эталонные решения и критерии для куратора взяты из документа без сокращений. Каждое эталонное решение мы прогнали по его тестам, все проходят. Исходник лежит в `backend/internal/seed/content.json`, при первом запуске сервер загружает его в базу сам.

**Ученик**
- входит по логину или регистрируется сам;
- на главной видит один следующий шаг, ниже свои курсы с прогрессом;
- на карте курса у каждого шага есть статус: не начат, зачтён, на проверке, возвращён, не прошёл;
- отвечает на вопросы с одним или несколькими вариантами и числом, результат приходит сразу;
- решает задачи на Python: код прогоняется по открытым и скрытым тестам, по каждому тесту виден вердикт OK, WA, TL, RE или CE;
- сдаёт ручные работы ссылкой, скриншотом или текстом, в зависимости от шага;
- пока работа у куратора, может идти дальше;
- видит комментарий, если работу вернули, и сдаёт её заново;
- смотрит историю всех своих попыток;
- задаёт вопрос по конкретному шагу и получает ответ там же;
- видит рейтинг с расшифровкой: сколько баллов за каждый шаг и тип шага, по какой формуле, какое место в группе.

**Куратор**
- работает с очередью ручной проверки, самые старые работы идут первыми;
- рядом с работой видит критерии проверки и условие шага;
- принимает работу с баллами или возвращает с обязательным комментарием;
- видит список закреплённых за ним учеников с прогрессом и сигналом «В графике», «Замедлился» или «Выпадает»;
- у сигнала всегда указана причина: не заходил несколько дней, три неудачные попытки подряд на одном шаге, отстаёт от среднего по группе на 25% и больше, не исправил возвращённую работу за два дня. Так отставание видно до того, как ученик перестанет заходить;
- отвечает на вопросы учеников.

**Администратор**
- создаёт курс, заполняет паспорт, публикует и снимает с публикации;
- правит уже опубликованный курс, ученики видят изменения сразу;
- собирает курс из модулей и шагов, меняет их порядок;
- у каждого шага настраивает содержание и способ проверки: правильный ответ, тесты, критерии, что сдаёт ученик;
- добавляет новый тип шага прямо в интерфейсе, без правки кода;
- записывает учеников на курс, назначает куратора, заводит пользователей.

**Как устроен шаг.** Тип шага и способ проверки у нас независимы. Тип отвечает за то, как шаг выглядит. Способов проверки четыре: засчитывается при прочтении, сверка ответа, прогон кода по тестам, проверка куратором. Все шаги хранятся в одной таблице, разница между ними лежит в двух JSON-полях. В первом то, что видит ученик. Во втором ответы, тесты и критерии, которые ученику не отдаются никогда. Поэтому новый тип шага не требует ни новой таблицы, ни правки сервера. Пример из ТЗ: шаг Scratch в одном месте проверяется числом автоматически, в другом ссылкой через куратора, и это один и тот же тип.

**Прогресс и рейтинг.** Любая сдача, автоматическая или ручная, пишется в одну таблицу. Прогресс и баллы считаются по ней, поэтому работа, принятая куратором, влияет на прогресс так же, как пройденный тест. Шаг зачтён, если есть хотя бы одна успешная попытка. Баллы по умолчанию: теория 1, вопрос 2, задача или задание 3, проект 5. Администратор может поменять их у любого шага.

**Оформление** сделано по брендбуку организатора: цвета, шрифты Onest и JetBrains Mono, статусы цветом и значком.

## Как запустить

Нужны Go и Python 3. Python проверяет решения задач. В `backend/go.mod` указан Go 1.27; если у вас версия старше, Go сам скачает нужную при первой сборке.

```bash
git clone https://github.com/lomen-Icarus/kotiki.git
cd kotiki/backend
go run .
```

Откройте http://localhost:8080. При первом запуске сервер создаст файл `backend/data/kotiki.db` и загрузит в него курсы и синтетических пользователей. Чтобы начать с чистой базы, удалите папку `backend/data`.

Настройки задаются переменными окружения, по умолчанию менять ничего не нужно:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `PORT` | `8080` | порт |
| `HOST` | все адреса | адрес, на котором слушать |
| `DB_PATH` | `data/kotiki.db` | файл базы |
| `UPLOAD_DIR` | `data/uploads` | куда сохраняются файлы учеников |
| `STATIC_DIR` | `../ХакатонLastVersion` | папка с интерфейсом |
| `PYTHON_BIN` | ищет `python3` | чем запускать решения |

Все запросы API с примерами описаны в [API.md](API.md), устройство сервера в [backend/README.md](backend/README.md).

**Стенд.** На сервере платформа работает от отдельного системного пользователя без прав, за nginx с сертификатом Let's Encrypt. Выкладка идёт через GitHub Actions скриптами из папки `deploy/`. При неудачном запуске релиз откатывается на предыдущий сам.

## Что в репозитории

| Папка | Что там |
|---|---|
| `backend/` | сервер на Go: API, база, проверка ответов и кода, прогресс, рейтинг, сигналы отставания |
| `ХакатонLastVersion/` | интерфейс, который отдаёт сервер |
| `deploy/` | скрипты выкладки на VPS, systemd-юнит, конфиги nginx |
| `Hackaton/` | предыдущая версия интерфейса, тоже умеет работать с сервером |
| `Demo_v6.1/` | самая ранняя версия, работает без сервера на localStorage, оставлена для истории |

## Что не успели

- **Песочница для кода учеников не полная.** На сервере решение запускается отдельным процессом с лимитами 256 МБ памяти и 2 с процессора, без сети, с файловой системой только на чтение. Но процесс идёт от того же пользователя, что и сам сервер, и при желании может до него дотянуться. Для настоящей эксплуатации решения нужно гонять в отдельном контейнере или через Judge0. При локальном запуске `go run .` сетевой изоляции нет вообще.
- **Файлы учеников** отдаются по прямой ссылке. Имя файла случайное и угадать его нельзя, но отдельной проверки прав нет.
- **Проверяется только Python.** Добавить другой язык можно отдельным способом проверки, но мы этого не делали.
- Нет восстановления пароля и подтверждения почты.
- Нет уведомлений: ученик узнаёт о проверке работы, когда заходит на платформу.
- **Без сервера интерфейс работает в демо-режиме** на localStorage: так открываются `Demo_v6.1/` и любая папка интерфейса, если открыть `index.html` как файл. В этом режиме решения на Python проверяются по шаблону, а не запуском. Для оценки нужна версия с сервером.

Оплату, CRM, расписание групп, посещаемость, мессенджер и видеосвязь мы не делали сознательно: по условию кейса они не входят в задачу.
