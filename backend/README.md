# Бэкенд образовательной платформы (Go)

Сервер на Go с базой SQLite. Отдаёт REST API (полное описание — [../API.md](../API.md)) и статические файлы фронтенда из папки `../ХакатонLastVersion` (если её нет — `../Hackaton`).

## Запуск

Нужны **Go 1.22+** и **Python 3** (для проверки задач с тестами).

```bash
cd backend
go run .
```

Откройте http://localhost:8080 — фронтенд, http://localhost:8080/api/health — проверка API.

При первом запуске создаётся файл `data/kotiki.db`, в который загружаются три курса из базового пакета (30 шагов) и синтетические пользователи. Чтобы начать с чистого листа, удалите папку `data/`.

Сборка одного исполняемого файла: `go build -o kotiki-server .`

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `PORT` | `8080` | порт |
| `DB_PATH` | `data/kotiki.db` | файл базы |
| `UPLOAD_DIR` | `data/uploads` | куда сохраняются файлы учеников |
| `STATIC_DIR` | `../ХакатонLastVersion` или `../Hackaton` | папка фронтенда |
| `PYTHON_BIN` | ищет `python3`, `python`, `py -3` | чем запускать решения |

Демо-входы (пароль у всех `1234`): `admin`, `curator`, `curator2`, `masha` и ещё 7 учеников — см. API.md.

## Устройство

```
backend/
├── main.go                    запуск: база → начальные данные → HTTP-сервер
└── internal/
    ├── db/                    схема SQLite и подключение
    ├── steps/                 ТИПЫ ШАГОВ И СПОСОБЫ ПРОВЕРКИ — главное место
    │   ├── types.go           реестр типов: theory, quiz, scratch, minecraft, code, project
    │   └── checkers.go        способы проверки: none, answer, tests, manual
    ├── runner/                запуск Python-решений по тестам
    ├── api/                   HTTP-обработчики
    │   ├── server.go          маршруты, авторизация, ошибки
    │   ├── catalog.go         каталог и страница курса
    │   ├── student.go         шаг, сдача ответа, история, рейтинг, вопросы
    │   ├── curator.go         ученики и сигналы отставания, очередь, проверка
    │   ├── admin.go           пользователи, конструктор курса, назначения
    │   ├── progress.go        расчёт прогресса, рейтинга и отставания
    │   ├── steptypes.go       типы шагов, добавленные администратором

    └── seed/                  начальные данные: content.json — перенос базового пакета
```

### Как устроены шаги (главное требование кейса)

Шаг описывается двумя **независимыми** свойствами:

- **тип** — как шаг выглядит: теория, вопрос, Scratch, Minecraft, задача, проект;
- **способ проверки** — `none` (прочитал — засчитано), `answer` (сверка ответа), `tests` (прогон кода), `manual` (куратор).

Все шаги лежат в одной таблице `steps`: различия хранятся в JSON-колонках `content` (что видит ученик) и `check_json` (ответы, тесты, критерии — ученик их не видит). Поэтому:

- **новый тип шага** — одна запись в `steps/types.go` или вообще без кода: администратор добавляет его на экране «Типы шагов» (`POST /api/admin/step-types`, таблица `step_types`). База, API и фронтенд не меняются: содержимое шага рисуется по `content_fields` типа, форма сдачи — по `submit.fields`;
- **новый способ проверки** (например, другой язык программирования) — новая реализация интерфейса `Checker` в `steps/checkers.go`;
- один тип может проверяться по-разному: у шага Scratch бывает ответ числом (автоматически) и ссылка на проект (куратор) — ровно как в базовом пакете.

### Прогресс и рейтинг

- Любая сдача — строка в `submissions`, будь то автоматическая или ручная проверка. Прогресс и баллы считаются по этой таблице, поэтому ручная проверка влияет на прогресс наравне с автоматической.
- Шаг засчитан, если есть хотя бы одна успешная сдача. Работа на проверке у куратора не блокирует следующий шаг.
- Баллы за шаг: теория 1, вопрос 2, разбор/задание/задача 3, проект 5 (можно менять для каждого шага). `GET /api/me/courses/{id}/rating` показывает разбивку по шагам и типам, формулу и место в группе.
- Сигнал отставания для куратора учитывает не только «давно не заходил», но и ранние признаки: застрял на шаге (3+ неудачных попытки), отстаёт от среднего по группе, не исправил возвращённую работу.

## Что не сделано / ограничения

- Решения на Python запускаются отдельным процессом с ограничением по времени, но **без изоляции** (не песочница) и без ограничения памяти. Для эксплуатации нужно запускать их в контейнере (Docker с `--network none`) или через Judge0.
- Пароли хранятся в виде bcrypt-хэша, сессии — случайный токен на 30 дней. Регистрации нет: пользователей создаёт администратор.
- Загруженные файлы отдаются по прямой ссылке со случайным именем, без проверки прав.
